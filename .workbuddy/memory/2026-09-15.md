## 🔴 二级目录上限（实测，重要）
- 平台报错「目录层级超限 — Skill 包仅支持两级目录结构（根目录/二级目录/文件），请移除子目录嵌套」。
- 含义：zip 内从 SKILL.md 所在根目录起算，**文件必须直接躺在二级目录里**，不能再套子目录
  （根 → 二级目录 → 文件 OK；根 → 二级 → 三级目录 → 文件 违规）。
- 本技能原结构 3 处违规：`scripts/vgui_runner/`（Python 包，7 文件）、`scripts/bash/`（11 文件）、`tests/fixtures/`（2 文件）。
- 修复（在 repo 内重构，CI 仍绿）：
  1. `scripts/vgui_runner/` → 技能根 `vgui_runner/`（包名 + 内部 `from .xxx import` 相对 import 全保留，仅改外部引用定位）。
  2. `scripts/bash/*.sh` → `scripts/`、`tests/fixtures/*.json` → `tests/`（拍平）。
  3. 路径注入：`scripts/gui_runner.py` 已有 `sys.path.insert(0, scripts/)`，追加技能根
     `sys.path.insert(0, _SCRIPT_DIR.parent)`；新增 `tests/__init__.py` 注入技能根
     （`unittest discover` 只塞 `scripts/` 和 `tests/`，不塞技能根，否则 `from vgui_runner.model import` 失败）。
  4. `references/xdotool-cheatsheet.md:42` 的 `scripts/bash/` → `scripts/`。
  - 关键事实：`python3 -m unittest discover tests` 从技能根跑，会把 **`scripts/`** 塞进 sys.path
    （不是技能根），这是 vgui_runner 原能 import 的原因 —— 所以不能把包简单提到根而不补路径注入。
- 验证：`unittest discover tests` 跑 **242 tests OK**；重打 zip 后文件最大深度 = 1（无三级嵌套），共 58 文件 / 141KB。
- 教训：平台技能打包 = frontmatter 必填字段（无 BOM）+ 两级目录上限，二者缺一不可，否则"解析失败/层级超限"。

## 🔴 live executor 在真实 daemon 上验证 + 修复（重要，可复用）
- 目标：用刚打包技能的 **live executor** 对 `dean-user1-36721`（IC25.1）跑 smoke，做真·活体验证。
- 从 GUI 主机（ubuntu-docker 本地）跑 live executor 最稳：远端有 `vcli`(~/bin)、`xdotool`(/usr/local/bin)、
  技能包已落 `/tmp/vgui-smoke/virtuoso-gui-debug/`、session 文件在 `~/cache/virtuoso_bridge/sessions/`。
  LocalRunner 本机跑 vcli 需 `VCLI_CAPABILITY=admin`（否则 skill exec 被拒）。
- 🔴 根因：daemon 进程（PID 51646）environ 里 **PATH 为空**（`tr "\0" "\n" </proc/51646/environ | grep ^PATH=` 返回空）。
  daemon 经 `sh -c` spawn 的 python helper 继承空 PATH → 按空 PATH 搜 `xwininfo`/`xdotool` 全 `No such file or directory`。
  - 注意：`/usr/bin/xwininfo` 与 `/usr/local/bin/xdotool` 都在，但 helper 子进程搜不到（daemon 用绝对路径 `/usr/bin/python3` 调起 helper，helper 内部 `subprocess.run(["xwininfo"])` 才按空 PATH 搜）。
  - `/usr/local/bin` 是 root 所有、user1 **不可写** → symlink 不可行；daemon 在跑也不能改运行中 env。
  - 后果：**`action-x11` 的 ALL 操作（activate/key/type/click/screenshot）在当前 daemon 上整条不可用**，不只 screenshot。
- 但 **`window screenshot`**（独立子命令，走 `hiGetWindowScreenDump` IC23.1+）与 `skill exec`（ciw_eval）在 daemon 上**可达**——前者不依赖 xwininfo/xdotool。
- 修复（在技能 `vgui_runner/live_executor.py` 的 `_run_action`）：
  1. screenshot 分支改用 `vcli window screenshot --path <out>/baseline.png`（经 `_vcli_argv_with_session`），不再走 `action-x11 --operation screenshot`。
  2. 归一化返回值 `status:"saved"` → `"success"`，否则 `_execute_action_step` 的 status 检查（`not in (None,"success")`）会把 "saved" 误判失败（EXECUTE_ERROR）。
  3. SSH runner 模式保留 scp 下载（result["path"] 而非 result["artifact"]["local_path"]）。
- 验证 PASSED：`{"status":"passed","failed_step":null,"error_code":null}`，RUNNER_EXIT=0。
  链路：precheck(会话+窗口 1306 绑定) → baseline(window screenshot) → execute(SCREENSHOT) → verify(ciw_eval 1+1==2)。
  实物证据：`/tmp/vgui-smoke-baseline.png`（6.1K，真实 daemon 截的 IC25.1 窗口）、summary.json `status:passed`。

  （scenario 只用 SCREENSHOT + ciw_eval 避开 action-x11）。要验 GUI 操作需修 daemon 启动 env（重启带 PATH）或改 live executor 走本地 xdotool。
