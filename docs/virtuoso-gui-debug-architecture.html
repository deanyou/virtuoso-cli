二、三种执行引擎

fake 离线

确定性回放，无子进程副作用，用于回归测试和逻辑验证

live 远程 vcli

通过 vcli 驱动真实 Virtuoso 会话，服务端窗口身份校验

local 直连 X11

直接 xdotool 操作本地 DISPLAY，无需 vcli，支持 SCROLL

用途：离线验证场景 JSON 合法性、状态机逻辑、回滚机制。不启动任何子进程，不接触 X11。

前置检查：仅验证 schema（字段、类型、超时范围 1-300s、重试 0-1）。

python3 scripts/gui_runner.py run scenario.json --output ./out --executor fake
# 输出: task.json / agent-actions.jsonl / summary.json
# 所有步骤 outcome 由 --fake-outcomes 注入，确定性可复现

用途：在真实 Virtuoso 会话上执行已验证的场景。所有 GUI 输入通过 vcli window action-x11，Rust 端每次重新解析和校验窗口身份。

前置检查（fail-closed，按序）：session 存在且端口匹配 → PID 正数 → DISPLAY 精确匹配 → PID 绑定唯一窗口 → 获取 DISPLAY 排他锁。

python3 scripts/gui_runner.py run scenario.json --output ./out \
  --executor live --session dean-user1-39471 \
  --vcli ~/virtuoso-stress-fix/target/release/vcli --ssh-host ubuntu-docker
# 支持 --direct (4.7x) 和 action-x11-batch (28x) 性能优化

用途：在有 X11 的机器上直接用 xdotool 操作，无需 vcli 二进制或 Virtuoso 会话。适合本地快速调试和 SCROLL 操作。

前置检查：xdotool 在 PATH → DISPLAY 可达 → PID 绑定可见窗口（或 --window-id 覆盖）。

python3 scripts/gui_runner.py run scenario.json --output ./out \
  --executor local --window-id 0x2600013
# SCROLL 映射 xdotool buttons 4(up)/5(down)/6(left)/7(right)
# 几何守卫: 零尺寸窗口拒绝点击, 越界坐标拒绝

Validate：严格 JSON schema 校验。未知字段直接拒绝；超时必须 1-300 秒；重试必须 0 或 1；每个操作必须有 verifier。VCLI_LOAD/VCLI_CALL 被 schema 接受但 live/local executor 拒绝执行（fail-closed）。
Precheck（live 模式，按序 fail-closed）：① session 在 vcli session list 中存在且端口匹配 ② PID 正数（旧桥接元数据零 PID 回退到窗口发现，无唯一绑定则拒绝）③ DISPLAY 与 X 服务器精确匹配 ④ PID 在该 DISPLAY 上绑定唯一窗口（0 或多个均中止）⑤ 获取 DISPLAY 排他锁并持有整个运行周期。
Execute：每个操作映射到固定 argv。live 模式走 vcli window action-x11（Rust 端重新解析窗口）；local 模式走 xdotool。--direct 跳过 helper 上传和 list-windows；batch 模式合并所有 xdotool 命令为一次 shell 调用。几何预检在 direct 模式下对 click-rel/drag-rel/scroll 做零尺寸和越界拒绝。
Verify：优先数据库优先谓词（通过 vcli 读 form 字段值），可见性谓词用 X11 窗口列表。验证失败且有 rollback 时执行恢复并重试；无 rollback 则标记步骤失败。CIW 读值（form->field->value）~425ms 确定性，截图+OCR ~20ms 但不可靠（±40px 漂移）。
Evidence：每次运行输出 task.json（验证后的场景快照）、agent-actions.jsonl（追加式事件日志，含每步 outcome 和耗时）、summary.json（最终 pass/fail + 错误详情）、window_<id>.png（截图）。typed 文本不出现在错误载荷中，替换为 text_length 标记。

四、性能优化分层（实测数据）

P0 — 默认用 xdotool，vcli 仅在需要服务端校验时 135×

vcli action-x11 每次 ~1350ms（Rust 启动 + X11 重连 + 窗口重解析）；xdotool ~10ms。几何用 xwininfo（3ms）替代 vcli list-windows（940ms）。

xdotool mousemove --window 0x2600013 300 167 && xdotool click 1 — 窗口相对坐标，无需 xwininfo/绝对坐标换算。vcli 仅用于：(a) 窗口身份需服务端验证 (b) live executor 模式 (c) xdotool 不可用。
P0 — vcli --direct 跳过 helper/list-windows 4.7×

必须用 vcli 时加 --direct：跳过 helper 上传、env 解析、list-windows 扫描。1213ms → 260ms。支持 activate/key/type/click-rel/drag-rel/scroll/close。

--direct 模式新增几何预检（PR #68）：click-rel/drag-rel/scroll 发送前用 xwininfo 验证窗口非零尺寸且坐标在范围内。越界坐标 exit=2 + 清晰错误信息。零尺寸窗口（最小化）用 geom cache（500ms TTL）快速拒绝。
P0 — action-x11-batch 合并 shell 一次往返 28×

连续操作（click→type→click...）用 JSONL batch，所有 xdotool 命令合并为一次 shell 调用。6 操作 260ms（vs 单独 7300ms）。非 direct 模式按唯一 DISPLAY 共享一次 list-windows。

每行一个 JSON action，支持 per-action 覆盖 pid/display。单操作失败不中止 batch。结果含 per-action status/duration/error。direct batch 新增 xwininfo 内存去重（同窗口多 action 只查一次几何）。
P1 — type delay 50ms → 10ms 4.4×

--delay 10 在 CIW 和表单字段中验证 6 轮无丢字。非 ASCII 用 15ms。20 字符输入 530ms → 120ms。

vcli action-x11 type 不可靠（注入乱码/剪贴板内容），始终用 xdotool type。xdotool type --clearmodifiers --delay 10 "METAL1"
P1 — 连续 xdotool 操作零 sleep

mousemove→click→mousemove→click 零 sleep 可靠（6 次快速 radio 点击全部触发回调）。仅在等待 Virtuoso 异步响应（表单重绘、对话框弹出）时用条件轮询。

用条件轮询替代固定 sleep：xwininfo 循环等待高度变化，或 vcli list-windows 等待对话框出现。避免"每次点击后 sleep 0.8"的保守做法。
P2 — 几何预检 + batch 共享 + geom 缓存 (PR #68)

direct 模式 xwininfo 预检（零尺寸/越界拒绝）；非 direct batch 按 DISPLAY 共享 list-windows；geom 文件缓存（temp_dir 跨平台，500ms TTL）零尺寸快速拒绝。

实测：SCROLL down:3 成功 528ms；direct 有效坐标 411ms；direct 越界 (9999,9999) 正确拒绝 exit=2；batch 非 direct 3 操作 1527ms（单 action 134-271ms）；geom 缓存文件写入正确几何。Windows/macOS/Linux 三平台 CI 全绿。

六、Virtuoso GUI API 语义沉淀（IC25.1 真机发现）

Tab 字段访问路径

Tab 内字段必须用 form->tabField->pageName->fieldName->value。直接 form->fieldName->value 返回 nil。

LayerCyclic 依赖 cellview

techGetTechFile(geGetEditRep()) 在无打开 cellview 时崩溃。必须 when(rep Tech=techGetTechFile(rep) ...) 守卫。

模态表单阻塞 vcli exec

hiDisplayForm 创建模态表单，阻塞 vcli skill exec（30s 超时）。读表单状态用 CIW 输入，不用 vcli exec。

菜单回调是字符串

hiCreateMenuItem ?callback "funcName" 点击后直接 eval 字符串。函数未定义时 CIW 报 undefined variable（回调确实触发了）。

ListBox value 永远是列表

即使单选，form->listbox->value 也是 list。读取用 car()，设置用 (list val)。Cyclic value 是单个字符串。

SpinBox 箭头 ~10px

xdotool 难以精确点击。优先 CIW 直接设值 form->spinbox->value = n。

lambda 语法需空格

lambda((x) body) 报错，必须 lambda( (x) body)。lambda() 空参不被接受。

return 仅在 prog 中

let 块中用 return 导致后续函数未定义。let 中最后一个表达式是隐式返回。嵌套 let((r "")) 报 illegal binding form，改用 prog((r)(setq r "")...(return r))。

CIW 输入可靠性

ctrl+a 在 Virtuoso 表单字段中不全选；用 Escape 清空 CIW 输入行。分号分隔多表达式时第二个赋值可能不生效，分步执行。大文件用 CIW load()，不用 vcli skill load（超时）。

vcli skill exec 无 UI 库

hiCreateAppForm/hiDisplayForm/hiGetFieldInfo 在 daemon exec 上下文中均为 nil。GUI 创建必须走 CIW 输入；交互走 xdotool/vcli action-x11；读状态走 CIW。

Toggle ?choices 格式

hiCreateToggleField ?value 必须是 t/nil 列表；?choices 每项必须是 (symbol label) 列表，用 stringToSymbol 转换字符串。

动态更新列表选项

form->field->choices = newList 动态更新 listbox/cyclic 选项，UI 立即刷新。设置对象属性用 = 操作符，不是 setq。
