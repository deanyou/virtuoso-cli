短周期 · Runtime Loop

Observe → Assert → Route → Execute → Verify → Recover。目标是让单次动作可靠。

长周期 · Learning Loop

Task → Failure/Success → Evidence → Diagnose → Experience → Regression → Promote。目标是让 Skill 随真实使用变强。

安全边界

Evolution allowed; uncontrolled self-modification forbidden。尤其 save/delete/overwrite 等 destructive 操作不允许在线自改 procedure。

06 · P1.7 State Model Promotion：不是新建状态，而是显式化现有状态

Current State Sources ├── CapabilitySnapshot │ ├── session / pid / display │ └── window / capabilities ├── RouteDecision │ ├── channel / risk │ └── provenance ├── VerifierResult / Evidence └── future promotion target ├── environment │ ├── host / display / ssh │ └── virtuoso_pid / session ├── design │ ├── library / cell / view │ └── dirty / revision ├── ui │ ├── active_window / modal │ └── focused_widget ├── execution │ ├── step / attempt / route │ └── risk_class └── verification ├── status / evidence └── checkpoint

Promotion Trigger / State Transition Contract

CapabilitySnapshot 当前够用。只有当 Router / Verifier / Recovery 出现重复状态传递、状态不一致，或 checkpoint/recovery 难以表达时，才把分散状态提升为一等 RuntimeState。

S0 = observe() assert precondition(S0) RouteDecision = route(action, S0) execute(RouteDecision) S1 = observe() verify(expected_transition(S0, S1)) commit(Evidence)

这比“截图看起来成功”可靠：能用 CIW/DB/window state 证明，就不依赖 OCR/Vision。

09 · 最终设计原则

Semantic First

能用 Virtuoso 语义状态控制和验证，就绝不依赖坐标与视觉。

Evidence First

执行成功不是“Agent 认为成功”，而是独立 Verifier 能证明后置条件。

Learn Above, Freeze Below

Skill/Knowledge 层可以持续学习；Runtime/Executor 层保持窄、确定、可测试、可恢复。Experience 可影响 procedure/context/recovery recommendation，但不能直接改 risk_class、permission、verifier requirement、retry budget 或 Router safety policy。
