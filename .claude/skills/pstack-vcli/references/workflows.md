# vcli 工作流

## 调查

从 CLI dispatch 进入相关 command，再追踪 client、transport 或解析器。回答输入来自哪里、输出形状、状态写入位置及失败如何传到退出码。动机问题用 git 历史补充；缺乏历史时明确未知。只读任务不创建测试文件、改配置或开 PR。对可运行的事实，用已有测试或隔离命令验证。

结论包含具体代码位置、证据和限制。源码可证明 `ok()` 的定义，但不能证明某个当前远程会话运行正常。

## 设计与功能

先定义用户看到的 JSON、输入边界、错误和退出码，再确定 Rust 数据结构与模块所有权。沿用项目现有模式。跨模块设计存在实质取舍时，可委派两个独立设计候选，比较调用者复杂度、共享状态和可测试性，再选择最小合适实现。

实现前明确阻塞前提、可以并行的文件范围和共享写入。有限资源下先完成一个可验证的纵向功能。固定成功/失败语义、安全边界、持久身份进入 binary；PDK 相关策略和多步设计流程留在 skill/script。

审阅实际变更，执行相关检查。新命令还需检查 clap 注册、dispatch、JSON 和失败退出码；`schema` 是手写描述，可能滞后，命令用法以当前 clap `--help` 和 dispatch 为准。

## 修复

先得到最小复现，记录命令、输入、预期、实际结果和环境。判断问题位于 CLI、transport、SKILL、PSF、GUI 还是外部依赖。对候选原因找能区分它们的观测，先验证机制再修改。

有便宜且稳定的现有测试入口时，先添加会失败的回归检查，确认失败原因正确，再修复并运行同一检查。复现需要昂贵实机环境时，用最接近问题的已有 fixture 并明确证据边界；不要因无法连接就伪造真实复现。

SKILL 的 `nil` 通过 STX 返回也可能是执行失败。检查 `skill_ok()` 与调用者要求的结果语义，避免用 transport `ok()`、额外 nil guard 或成功默认值掩盖失败。仿真缺失 PSF 时先检查 simulation success；AC 无幅值时先检查激励 `mag`。

传输超时涉及写操作时，不直接重试整个命令。查清副作用是否发生，再按幂等性和当前授权处理。

## 重构

列出保持不变的用户契约，包括 JSON、退出码、环境变量优先级、会话路径和并发清理。用现有测试锁定行为后修改结构。内部 API 的调用者与旧 API 在同一波迁移；外部公开契约的兼容性按用户要求处理。

逐块验证，不把重构扩展成新功能。不要为了方便中间状态添加最终不需要的兼容层。

## 性能

固定输入、环境、工作量和指标，先测基线。区分 SSH 建连频率、桥接往返、Virtuoso 运算和本地解析成本。每次只验证一个有机制解释的假设，记录前后值及误差。改善真实指标才保留修改；避免把离线 mock 的时间当作真实 EDA 性能。

## 审查

读取实际 diff、相关调用者和已有测试。可以把 transport/SKILL 边界、会话并发、CLI 合约和 Python 工作流拆为独立只读审查。

优先找可触发的故障：STX/nil 误判、未转义字符串、错误退出码、全局缓存竞争、非幂等重放、`unavailable` 算成功、compute/jump 配置混淆。每条问题说明触发条件、用户影响和具体位置。未发现问题时如实报告，不为了评审数量生成修改。

## 技能适配

先检查上游 `SKILL.md`、引用、脚本依赖、许可证和授权假设。保留与项目相关的行为，替换实际不存在的工具和模型；不要把不可运行的原样副本标为安装完成。

技能 frontmatter 使用合法名称和描述，引用在安装位置可解析。保留来源、上游版本和许可证。通用确定性检查写成脚本并实际运行。新脚本至少验证成功、失败、超时与证据保留这些有意义的行为。

有复杂路由时，用独立代理在隔离目录处理真实请求；只给技能与原始问题，不给预期答案。检查实际产物，区分静态格式验证、代理行为测试与产品实机验证。
